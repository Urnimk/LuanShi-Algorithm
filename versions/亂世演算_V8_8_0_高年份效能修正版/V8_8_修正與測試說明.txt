亂世演算 V8_9｜高年份效能修正版

本版新增：國家詳細查詢的「完整奪冠紀錄」標題，在奪冠次數右側顯示「歷史最高戰力」。數值取自該國全部政權世代編年史 peak_power 的最大值，並納入目前戰力。

一、結論
以您提供的 V8_7 程式及 saves_1005.zip 為準。本存檔為第 139,747 年、100 國，累積 24,983 筆國家編年史。
國家快照 7,964,015 bytes，其中緊湊 JSON 編年史約 6,740,770 bytes（84.6%）。
您的懷疑方向正確，但瓶頸應精確區分：每年更新當代巔峰資料本身很快；每年重新序列化、寫入整份累積歷史，以及 UI 讀取與重建表格，才是問題重點。

二、程式證據（原 V8_7）
1. 主程式 _atomic_write_json() 使用 json.dump()，compact 模式仍逐片段呼叫 write。年度存檔位於 thread_stat_monitor() 尾段，整份 countries 包含所有 country_chronicle，一併輸出；並複製上一份檔案為 .bak。
2. _chronicle_update_live_stats() 更新當代巔峰與排名；_chronicle_start_current() 才在世代開始時新增紀錄。並不是每年新增 100 筆歷史，也不是開啟 100 個独立編年史檔案。
3. UI 每 1500 毫秒重新解析國家與聯盟檔，即使檔案未變動。update_ui_data() 也會呼叫未開啟的編年史頁面。
4. on_chronicle_country_selected() 的 signature 包含 current_year，年份一變就刪除及重新插入全部世代列。資料越多，Tk 主執行緒越容易被阻塞。
5. Q 表每 10 年儲存一次，另有屆末儲存，因此可能形成週期性停頓。這份 Q 表約 14.3 MB。
6. 外交快照另保留 1,177 筆聯盟戰爭投票、1,128 筆入盟投票。這些累積資料也增加讀寫成本；本版未刪除任何歷史紀錄。

三、V8_9 修改
1. 緊湊 JSON 改用 json.dumps() 快速編碼後一次 write，保留原子替換、.bak、JSON 結構及原存檔頻率。
2. UI 以檔案時間（奈秒）、大小及 inode 快取解析結果；檔案改變才重讀。讀取失敗不更新快取，下輪可恢復。
3. 編年史僅在使用者開啟該頁面及分頁時定時刷新。
4. 同國家、世代數不變時只修改變動的表格列，保留捲動與選取。切換國家或新增世代才重建。
5. 啟動器、引擎及視窗版號改為 V8_9。無新增玩法，無 AI 狀態／行動、平衡參數或存檔架構變動。

四、驗證結果
環境：Linux / CPython 3.12，無 GUI，從原始存檔續跑到第 139,767 年，共 20 年。使用原有 MAX_TURNS 與 LOOP_DELAY 測試開關，關閉人工等待。
不開效能剖析、包含載入與續跑的單次耗時：
V8_7：11.480 秒
V8_9：4.607 秒
耗時降低 59.9%，約 2.49 倍處理速度。
這是本機單次短程比較，不代表 Windows 實際畫面 FPS 或長時間測試保證。

剖析工具下，原版整體 101.64 秒，其中 _atomic_write_json 累積 94.99 秒；編年史 ensure/update 累積約 0.082 秒。剖析會大幅放大 Python 逐片段編碼成本，因此不以剖析時間計算實際加速倍率。

一致性：兩版 20 年後的國家、外交／戰爭、Q 表及進度 JSON，排除版號、隨機快照識別碼與儲存時間後完全一致。
其他：Python 語法編譯通過；三種主要存檔的輸出位元組與備份內容一致；JSON 快取未變動／替換／損毀後恢復測試通過；模擬 Treeview 驗證年度更新只修改 1 列、新增世代可重建。
未進行真實 Windows Tkinter 畫面操作與多日穩定性測試。

五、為什麼沒有改成只有政權交接才存
單純取消年度巔峰更新會遺漏中途最高戰力、人口與最佳排名。即使停止這項更新，整份 countries 仍會每年寫入，並不能消除主要瓶頸。
V8_9 先以相容方式改善速度，保留全部歷史與每年存檔。
限制：每年完整快照及 .bak 複製仍存在，檔案仍會隨歷史成長；這次減少處理成本，並未消除無限累積的資料量。
如果未來改為「現行世代在記憶體每年更新、交接／滅國時封存歷史、輕量即時快照與歷史檔分離」，就涉及存檔架構及恢復機制，依您的規則應列 V9；不宜只把寫入呼叫關掉。

六、使用方法
1. 完全關閉原版遊戲。
2. 將本 ZIP 解壓至新資料夾。
3. 把現有遊戲的整個 saves 資料夾複製到新資料夾，與 Python 程式並列。勿同時讓兩個版本寫入同一份 saves。
4. 啟動「亂世演算_V8_9_啟動.py」。若由命令列啟動：python 亂世演算_V8_9_啟動.py
5. 確認視窗為 V8_9，年份接續原進度。沒有 saves 時會依原設計建立新局。
本包不附測試後存檔，避免覆蓋您的遊戲進度。原存檔與原版壓縮檔未修改。

版號規則：相容修正與既有功能改善用 V8_9 等底線版本；重要新系統、核心玩法、狀態／行動或存檔架構改變升整數大版。
